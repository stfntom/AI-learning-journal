## 阻碍1：Dify首页渲染错误

**现象**：打开 cloud.dify.ai，页面标题"主页 - Dify"，但中央报"渲染此组件时发生了意外错误"，点"重试"无效。

**排障流程（按顺序执行）**：

1. 点页面内"重试"按钮 → ❌ 无效
2. F5 / Ctrl+F5 强制刷新 → 仍报错
3. **外部站判断法**：访问 docs.dify.ai（Dify官方文档站）
   - 文档站能打开 → 网络到Dify服务器没问题，问题只在cloud应用页本身
   - 文档站也打不开 → 才是网络/代理问题
4. 实测：文档站正常 → 从文档站顶部"试试Dify"按钮绕进 cloud.dify.ai → ✅ 恢复，且已是登录态

**方法论提炼**：同一域名下多个子服务，用一个"已知健康的姊妹站"快速二分定位：是网络问题还是应用问题。**先判断，再动手**，避免盲目清缓存折腾。

## 阻碍2：应用类型里没有"聊天助手"

**现象**：创建空白应用弹窗里只有"工作流"和"ChatFlow"两项，没有教程里说的"聊天助手/Agent"。

**解决**：选 **ChatFlow**（支持记忆的多轮对话工作流），符合学习规划机器人形态。应用名"学习规划私人订制师"。

**教训**：新版Dify已改版，教程（含官方文档）可能滞后——**以自己屏幕上看到的实际选项为准，不按教程硬找不存在的选项**（这正是Day11在Coze踩过的坑，今天没重蹈）。

## 阻碍3：单节点测试报"sys.files不能为空"

**现象**：测试运行LLM节点时，sys.files 被标红"不能为空"，无法运行。

**原因**：LLM节点的USER输入框里引用了 `#files#` 变量，测试环境把它当成必填项。

**解决**：USER框里删掉 `#files#`，只保留 `#query#` → ✅ 通过。

## 阻碍4：插入知识检索节点后，LLM节点丢失+Prompt被清空

**现象**：在"用户输入"和"LLM"之间插入知识检索节点后，画布变成"用户输入→知识检索→直接回复"，**LLM节点没了**；重新插入LLM后，SYSTEM框里的Prompt v3被清空。

**原因**：插入节点挤掉了原连线上的下游节点；新插入的LLM节点是空白节点，不带旧配置。

**解决**：
1. 在"知识检索→直接回复"连线上再插入LLM节点
2. 重新粘贴Prompt v3到SYSTEM框
3. 最终流程：**用户输入 → 知识检索 → LLM → 直接回复** ✅

**教训**：改画布结构前，先把Prompt存一份在本地文件（已有项目规范v0.1.md备份，所以恢复只用了30秒）。

## 阻碍5：机器人原样回复"llm.text"七个字符（最典型的坑）

**现象**：全局运行成功，但聊天面板里机器人的回复只有"llm.text"这一行字。

**原因**：直接回复节点的"回复内容"框里，`llm.text` 是**手打的普通文字**，不是变量引用。系统就把它当文本原样输出了——相当于Excel单元格里输入了"=A1"的字面文字而不是公式。

**判断证据**：节点输出JSON显示 `"answer": "llm.text"`——如果变量真被解析，answer里应该是完整规划文本。

**解决**：删掉手打文字 → 在输入框输入 `{`（或点 `{x}` 变量按钮）→ 弹出变量选择菜单 → 选 **LLM → text** → 框里出现变量芯片（不是蓝色文字）→ ✅ 机器人正常回复。

**方法论提炼**：**手打的变量名 ≠ 变量引用**。变量必须通过选择菜单插入成"芯片"才算数。判断方法：看输出——如果机器人把你写的变量名原样念出来，就是没接上。

## 阻碍6：如何确认RAG真的接通了？（不靠感觉，靠数据）

**问题**：知识检索节点在画布里存在≠它生效。怎么验证考纲内容真的进了模型？

**方法：看 prompt_tokens**

| 运行 | prompt_tokens | 结论 |
|---|---|---|
| 单节点测试LLM（知识检索未执行） | 342 | ≈系统提示词本身，考纲没进去 |
| 全局运行（完整流程） | 1576 | 明显变大，考纲片段确实被塞进上下文 ✅ |

**方法论提炼**：**token消耗量是RAG是否生效的硬证据**。如果接了知识库但prompt_tokens没涨，说明检索结果没进LLM——别看流程图"看起来对"，看数据。

## 阻碍7：机器人反复发问卷，不出规划（未解决，Day13决策点）

**现象**：连续3轮对话（含一次信息补全、一次强硬指令"直接输出不要反问"），机器人每次都回复信息收集问卷，且明确说"目前还没有提供考纲"。

**根因分析**：Prompt v3的约束触发条件是"**用户未提供考纲、教材或真题时，所有具体考点标注待核对**"。知识库里的考纲虽然能被检索到（阻碍6已验证），但**模型不把知识库内容算作"用户已提供考纲"**——两者在它眼里是两回事。所以RAG管道通了，约束逻辑还是走"未提供"分支，且模型为求稳先收集信息。

**当前状态**：搁置。修复需要在Prompt里加一句"知识库中的考纲视为已提供考纲"，但这触及禁区（不在Prompt层修"考点待核对"），需用户Day13授权决策。

**今天的收获**：把问题从"感觉不对劲"精确定位到"Prompt触发条件与知识库的认知错位"——问题定义清楚了，解法只是一个句子的事。

## 今日排障方法论总结（可复用）

1. **二分定位**：网络问题 vs 应用问题，用姊妹站（docs站）快速判断
2. **以实际界面为准**：教程/文档可能滞后，屏幕上有什么就用什么
3. **输出反推配置**：机器人原样念出变量名 = 变量没接；answer里是文本 = 变量已解析
4. **token数验证RAG**：prompt_tokens不涨 = 检索结果没进模型
5. **改结构前备份配置**：Prompt存本地，节点重构后秒恢复
6. **问题定位优于动手修复**：阻碍7今天没修，但根因已锁死，明天一句话可解
